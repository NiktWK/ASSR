# Соответствие ТЗ и проверка

ТЗ 0.1 описывало полноценный исследовательский MVP. Здесь реализован его исполняемый первый вариант, ограниченный JSON бинарной классификацией. CPU демонстрация и automated tests проверяются локально; подключение реального GPU, внешнего LLM и развёртывание PostgreSQL/MLflow требуют отдельного acceptance run в целевой среде.

| Критерий | Реализация и проверка | Статус в среде разработки |
|---|---|---|
| AC01 baseline + treatment × 3 seed | Полный измеряемый CPU цикл, smoke, итоговый отчёт | Проверено CPU; GPU не проверен |
| AC02 hashes и артефакты | RunSpec + validate_run; отсутствие evidence блокирует вывод | Автотест |
| AC03 нет повторного GPU job | Durable intent, ключ, Docker name, inspect, flock | Fake Docker + сбой между submit и записью; нужен GPU тест |
| AC04 восстановление | SQL snapshot, перезапуск Engine, человеческий gate и RUNNING | SQLite автотест; PostgreSQL ждёт deploy |
| AC05 stale code и данные | digest gate, allowlist, защищённый evaluator, split check | Автотест |
| AC06 OOM, NaN, timeout, SSH | reason codes, проверка predictions, сохранение job identity | Fault injection; реальные OOM/SSH нужны отдельно |
| AC07 бюджет и cancel | Резерв до side effect, tombstone, cancel_pending, timeout | Автотест контрактов; реальные 60 секунд не измерены |
| AC08 изоляция | Network none, non-root, read-only, no socket/secrets, quota gate | Проверка argv; реальный penetration smoke не выполнен |
| AC09 воспроизводимость | Повтор одного fixture seed, фиксированные source/config/data | CPU проверка; CUDA tolerance задаётся оператором |

## Выполнить на целевом GPU хосте

1. Воспроизвести baseline и выставить ожидаемую метрику/допуск до treatment.
2. Отправить один и тот же submit дважды и после потери ответа; проверить ровно один training container и job_id.
3. Остановить API во время RUNNING, перезапустить и дождаться исходного job без нового назначения.
4. Искусственно вызвать CUDA OOM и timeout; проверить причины и отсутствие выдуманных результатов.
5. Отключить SSH во время cancel: UI должен показывать cancel_pending; walltime завершает job; после восстановления состояние согласуется.
6. Проверить недоступность labels, секретов, Docker socket и внешней сети из training; попытка записи в source/data должна завершаться отказом. Переполнение output должно останавливаться квотой.
7. Провести 3 seed baseline/treatment, проверить независимый evaluator, MLflow links, журнал решений и повтор результата в установленном допуске.
8. Зафиксировать версии драйвера/CUDA/образов, провайдера LLM, фактические расходы и протокол проверки в отдельном отчёте.

## Явные отклонения и дальнейшая работа

- RD-Agent не проходил обещанный временной пилот; выбран документированный fallback LangGraph (ADR 001).
- Smoke команды задаёт профиль. Универсальное автоматическое построение качественных unit tests для любой архитектуры не реализовано; example PyTorch содержит проверки forward/backward, loss и gradients.
- Test-набор закрыт целиком: текущий результат относится к validation. Финальная test оценка, ablations и более сложные статистические методы требуют расширения protocol/evaluator adapter.
- Нет встроенного поиска литературы, Slurm, multi-node, автономной публикации, многоарендности, секретного менеджера или автоматической очистки артефактов.
- Дисковая квота — требование к хосту; rootless Docker не является доказанной изоляцией для враждебного кода на общем критичном сервере.
- Все зависимости Python закреплены uv.lock. Инфраструктурный Compose и CUDA пример не запускались в среде без Docker/GPU.

Система не считается полностью принятой по ТЗ до выполнения целевого GPU acceptance run. Это ограничение проверки не скрывается за успешным демонстрационным прогоном.
