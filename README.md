# ASSR — команда из четырёх opencode-агентов + секретарь

Минимальная оркестрация четырёх ролей поверх `opencode serve` и Telegram-бот для
управления. Система только маршрутизирует сообщения между агентами — она не оценивает
содержание их работы.

```
человек ── Контролёр ── Исследователь ── Разработчик
   │                               └──── Тестировщик
   └── Секретарь (Telegram, от лица человека)
```

- **Контролёр** — критик процесса исследователя: сверяет его Plan/Build с заданием
  пользователя, при несоответствии спрашивает человека.
- **Исследователь** — ищет источники, декомпозирует задачу, проектирует архитектуру,
  вызывает разработчика и тестировщика, проверяет их Plan/Build и делает выводы.
- **Разработчик** — код и unit-тесты к нему.
- **Тестировщик** — проверка существенной части (симулятор, реальные прогоны) и отчёт.
- Разработчик и тестировщик напрямую не общаются — только через исследователя.
- **Секретарь** — личный помощник оператора: видит состояние и историю, отвечает на
  вопросы, отвечает агентам от лица человека, запускает/отменяет прогоны и передаёт
  указания контролёру.

У каждой роли две фазы, у каждой фазы свой промпт: `prompts/<role>-<phase>.md`.
Роль = отдельная долгоживущая opencode-сессия; фаза переключается профилем агента
в сообщении (`controller-plan`, `controller-build`, ...).

## Запуск

```bash
python3 team.py run "Создай в workspace/ модуль калькулятора с unit-тестами и проверь их"
```

Оркестратор сам поднимает `opencode serve` (если ещё не запущен) и печатает команды
для наблюдения за каждой сессией в реальном времени:

```bash
bash run/attach.sh controller   # или researcher / developer / tester
# то же самое:
opencode attach http://127.0.0.1:4097 -s ses_... -p <пароль> --dir "$PWD"
```

Полезные команды:

```bash
python3 team.py watch                   # живая лента событий + вопросы человеку
python3 team.py status                  # фазы, задачи, открытые вопросы
python3 team.py events -n 50            # журнал событий (без live)
python3 team.py answer q3 "approve"     # ответ человеку (approve/revise для плана и финала)
python3 team.py cancel                  # отменить активный прогон
python3 team.py stop                    # остановить поднятый сервер
```

В интерактивном терминале (`run`) вопрос человеку можно отвечать прямо в консоли;
в фоне (nohup/CI) — командой `team.py answer` или из Telegram.

## Прогоны, продолжение и сохранность истории

Каждый прогон живёт в своём каталоге `run/runs/<run_tag>/` (тег = дата-время старта):

```
run/runs/<run_tag>/
  state.db        состояние прогона (sqlite)
  chat/<role>.md  переписка с каждой ролью
  events.log      журнал событий
  console.log     вывод оркестратора этого прогона
  sessions.json   манифест: тег, задача, роль → id сессии
  backups/        автокопии state.db (последние 10)
```

`run/current.json` — «ярлык», указывающий на активный прогон; бот и инструменты
находят состояние по нему. Ничего не удаляется: новый прогон создаёт новый каталог,
предыдущие остаются на месте, доступны и возобновляемы.

```bash
python3 team.py runs                       # список сохранённых прогонов (тег, статус, задача)
python3 team.py run --resume               # продолжить текущий прогон (те же сессии, без сброса)
python3 team.py run --resume <тег>         # переключиться на указанный прогон и продолжить
python3 team.py run "<задача>"             # новый прогон; при наличии сохранённого нужен явный --fresh
```

`--fresh` ничего не удаляет — просто начинает новый каталог. Если база состояния
повреждена или потеряна, автокопии (`run/runs/<тег>/backups/`) позволяют продолжить
с последней копии. В Telegram продолжение — командой `/resume [тег]`.

## Telegram-бот

Зависимость уже стоит (`aiogram 3.21`); зафиксирована в `requirements.txt`:

```bash
pip install -r requirements.txt
```

Токен и чат — через env, иначе через `run/telegram.json` (права `600`, каталог в `.gitignore`):

```bash
export TELEGRAM_BOT_TOKEN="123:ABC"
export TELEGRAM_ALLOWED_CHAT_ID="123456789"
# или: echo '{"token":"123:ABC","chat_id":123456789}' > run/telegram.json && chmod 600 run/telegram.json

python3 tg_bot.py --check     # проверить токен
python3 tg_bot.py --whoami    # подсказать chat_id (напишите боту /start)
python3 tg_bot.py             # запустить бота
```

Бот — отдельный процесс; оркестратор запускается им по команде. Одновременно
выполняется только один прогон.

Команды:

- `/newtask <цель>` — запустить прогон (если активный уже есть — отказ).
- `/resume [тег]` — продолжить сохранённый прогон (по умолчанию текущий).
- `/status`, `/tasks`, `/events [n]` — состояние, задачи, метаданные событий.
- `/questions` — открытые вопросы с кнопками.
- `/answer qN <текст>` — ответить; также можно ответом (reply) на сообщение с вопросом.
- `/cancel` — отменить прогон (с подтверждением).
- `/models` — модели всех профилей: что в конфиге и что фактически было в последнем ходе.
- `/setmodel <target> <provider/model>` — сменить модель. Цели: `controller-plan` … `tester-build`,
  `secretary`, шорткаты `controller|researcher|developer|tester` (обе фазы), `all`.
- `/ask <вопрос>` или любой обычный текст — **секретарь**.

Вопросы приходят с кнопками: «✅ Принять» / «✏️ Доработать» для плана и финала,
«✏️ Ответить» для вопроса контролёра. Прогресс приходит только метаданными
(кто что сдал/принял, задачи, вопросы). **История диалогов агентов в Telegram не
отправляется**; секретарь при этом имеет к ней доступ и может отвечать по существу.

### Смена моделей

`/setmodel` сначала проверяет модель живым запросом и только затем пишет `opencode.json`
(атомарно, с бэкапом в `run/opencode.json.bak`).

- **Идёт прогон, меняются только модели**: сервер не трогается. Оркестратор читает
  модель из `opencode.json` при каждом ходе (per-message override), поэтому смена
  применяется со следующего хода нужной фазы — без остановок и разрывов.
- **Идёт прогон, но изменены инструменты/промпты** (нужен перезапуск процесса):
  изменение откладывается до завершения прогона — сервер на ходу не перезапускается.
- **Прогона нет**: конфиг перезагружается сразу (`/instance/dispose`, при необходимости —
  перезапуск сервера с сохранением порта и пароля).

Неприменённые изменения переживают перезапуск бота (`run/models_pending.json`).

## Секретарь

Постоянная сессия `team/secretary` (id в `run/secretary.json`), переживает сброс
`state.db`. Инструмент `assistant` (`.opencode/tools/assistant.ts`):

`status`, `tasks`, `events`, `questions`, `question`, `answer`, `start`, `stop`,
`tell_controller`, `result`.

Секретарь может читать весь проект, включая `run/chat/`, но не меняет файлы и не
пишет код. По явной просьбе оператора он может менять модели агентов:
`assistant models` (что стоит) и `assistant setmodel {target, model}` — с той же
живой проверкой; запись в конфиг и постановка в очередь на безопасную перезагрузку. `start`/`stop` — по явной команде; `tell_controller` передаёт формулировку
оператора контролёру текущего прогона (оркестратор доставляет её после текущего шага).
Сессию секретаря можно смотреть на хосте:

```bash
python3 -c "import json;print(json.load(open('run/secretary.json'))['attach'])"
```

## Согласование

Каждый результат фазы сдаётся инструментом `team submit` и уходит на сверку выше:

| Исполнитель | Сверяет |
|---|---|
| разработчик, тестировщик | исследователь |
| исследователь | контролёр |
| контролёр | человек |

Вердикт — `team review` (`approve` / `revise` с замечаниями). `revise` возвращает
исполнителя в ту же фазу. Вопросы — `team ask` (вверх по иерархии) и `team answer`.
Задания исполнителям выдаёт только исследователь (`team assign`).

## Протокол `team` и `assistant`

`submit`, `review`, `assign`, `ask`, `answer`, `sources`, `status` — в
`.opencode/tools/team.ts` (opencode → `python3 team_agent.py` → sqlite).
`team_agent.py` проверяет, что сессия принадлежит роли, а фаза соответствует действию.
`assistant` — в `.opencode/tools/assistant.ts` (opencode → `python3 assistant_agent.py`);
инструмент доступен только сессии секретаря из `run/secretary.json`.

## Файлы

```
opencode.json            9 профилей агентов (4 роли × 2 фазы + секретарь)
prompts/                 промпты ролей/фаз и секретаря
team.py                  оркестратор: HTTP-клиент, машина состояний, CLI
team_agent.py            бэкенд инструмента team
team_db.py               состояние (sqlite): сессии, фазы, задачи, вопросы, события
run_control.py           старт/отмена/проверка активного прогона
tg_bot.py                Telegram-бот (aiogram 3): команды, кнопки, прогресс, секретарь
assistant_agent.py       бэкенд инструмента assistant
.opencode/tools/team.ts      custom tool "team"
.opencode/tools/assistant.ts custom tool "assistant"
tools/websearch.py       поиск Bing без ключей (stdlib) для исследователя
workspace/               рабочая область агентов (код, тесты, отчёты)
run/                     общие файлы (server.json, orchestrator.pid, cancel,
                         bot_state.json, telegram.json, secretary.json, логи) и
                         runs/<run_tag>/ — каталоги сохранённых прогонов
```

Права: plan-фазы — только чтение; `developer-build`/`tester-build` могут менять
файлы только внутри `workspace/` и запускать bash; исследователю разрешён только
`python3 tools/websearch.py *`; секретарю — чтение и `assistant`. Модели задаются
в `opencode.json`.
